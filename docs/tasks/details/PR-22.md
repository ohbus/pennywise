# PR-22 — Remove production in-memory persistence fallbacks

- Phase: production_hardening
- Owner role: coordinator
- Dependencies: PR-17, AUTH-03, FND-08
- Owned paths: `app/notifications/src/main/kotlin/com/subhrodip/pennywise/notifications/inbox/`, focused Notifications tests, and this task detail

## Objective

Close CRIT-05 by ensuring Spring production wiring cannot silently select an
in-memory notification store.

## Acceptance criteria

- `NotificationInbox` has no constructor default that creates process-local storage.
- Production and staging contexts resolve the JPA inbox adapter or fail startup.
- In-memory storage remains available only through explicit test construction.
- Focused controller and JPA inbox tests pass.

## Validation

- `./gradlew.bat :app:notifications:test --rerun-tasks --no-daemon`
- `git diff --check`

## Current increment

Removed the constructor default that silently selected
`InMemoryNotificationInboxStore`. Spring wiring now requires the JPA adapter;
unit/controller tests construct the in-memory adapter explicitly. The full
Notifications test task passes.
