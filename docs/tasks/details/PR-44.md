# PR-44 — Serialize GraphQL subscription admission

- Phase: production_hardening
- Owner role: coordinator
- Dependencies: PR-20, PR-43
- Owned paths: BFF live fanout and focused tests, and this task detail

## Objective

Make the per-user GraphQL subscription bound atomic so concurrent connection
attempts cannot bypass the configured limit.

## Acceptance criteria

- Expired subscriptions are removed before admission.
- The limit check and insertion are one atomic critical section.
- Concurrent admission cannot create more than the configured subscriptions
  for one user.
- Existing expiry, revocation, and queue behavior remains passing.
