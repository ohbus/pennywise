# DB-05 — Add reader health, lag, circuit breaking, and fallback policy

Implement reader health state, replay-lag measurement, stale-budget checks,
circuit breaking, bounded writer fallback, and classified temporary-unavailable
errors. Fallback must be policy-controlled and must not consume writer capacity
unboundedly.

Acceptance covers healthy, lagging, disconnected, exhausted, circuit-open, and
recovered readers; route metrics and alerts are emitted; no write retries or
silent consistency weakening occur.

## Concrete code targets

- Add reader health and circuit state under `libs/db/.../health` and integrate it with `DbRoutingDataSource`.
- Add PostgreSQL replay-lag probe SQL and a bounded scheduler; probe credentials must be read-only and service-scoped.
- Extend `libs/observability` metrics and `infra/observability/prometheus.yml`/rules with route, lag, pool, fallback, and circuit alerts.
- Add failure tests using the existing PostgreSQL integration-test conventions in `app/expense-core/src/test` and shared `libs/db/src/test`.
- Document operator behavior in `docs/operations/` including forced writer-only mode.
