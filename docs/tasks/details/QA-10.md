# QA-10 — Repository-wide test gap audit and closure

## Objective

Identify and close missing unit, controller, persistence/messaging integration,
and deployed E2E coverage across every production branch. Maintain explicit
acceptance criteria and evidence boundaries so a passing lower-layer test is
not reported as deployed or production proof.

## Dependencies

- QA-07 — public operation inventory and local E2E matrix
- QA-08 — production-like validation procedures and environment gates
- ERR-10 — catalogued error and negative-path behavior

## Acceptance criteria

1. Every production class/method/branch is mapped to unit, transport,
   persistence/messaging, live E2E, or an explicit structural classification.
The current regenerated JaCoCo baseline contains 148 methods with 366 missed
   branches across the nine application/library modules; each must be
   classified or closed individually.
2. Every missing row has an exact target path, test layer, invariant, failure
   behavior, side-effect assertion, and acceptance criterion.
3. All 45 REST operations and 9 GraphQL roots retain operation-level evidence,
   while authorization, replay, failure, concurrency, pagination, and side
   effects are tracked separately.
4. Security, financial, identity, outbox, notification, cursor, and error paths
   cannot close on status-only assertions; durable state and redaction are
   asserted where applicable.
5. Production-scale, failover, restore, rollback, rotation, alerting, and
   distributed WebSocket evidence remain environment-gated and are not inferred
   from local Docker or mocked tests.
6. Each closure increment records exact commands, results, source revision,
   generated coverage, and residual limitations.
