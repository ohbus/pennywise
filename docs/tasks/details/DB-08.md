# DB-08 — Split Accounts command and query ports

Keep credential/session state, rate limits, token consumption, export/deletion
transitions, and auth-email outbox on the writer. Introduce explicit query ports
for only approved profile/preferences reads, with causal follow-up support.

Acceptance covers authorization, privacy, read-after-write, replica failure,
writer fallback, and all existing Accounts authentication/persistence suites.

## Concrete code targets

- Keep `LoginCredentialService.kt`, `LoginCredentialRepository.kt`, `TokenSessionService.kt`, `AuthSessionRepository.kt`, `LoginRateLimitService.kt`, and `RateLimitBucketRepository.kt` on the command route.
- Keep `LoginVerificationService.kt`, `LoginStartService.kt`, `AuthEmailOutboxService.kt`, `AuthEmailOutboxRepository.kt`, and `AuthEmailOutboxPublisher.kt` writer-only.
- Split `profile/ProfileStore.kt` and `JpaProfileStore.kt` into an authorization-aware command port and bounded read DTO port; profile reads are the only initial replica candidates.
- Update `ProfileController.kt`, profile repository tests, `AuthPersistenceTest`, `JpaRequestStoresTest`, and profile persistence tests with route and causal assertions.
- Keep `ProductionSecurityConfig.kt` and all JWT/session validation independent of reader routing.
