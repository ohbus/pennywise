# DB-15 — Migrate remaining approved query capabilities

Promote query capabilities individually using the operation catalog and pilot
evidence. For each capability document authorization source, freshness budget,
route policy, indexes/projection, fallback, metrics, and rollback.

Acceptance requires no blanket GET/read-only routing, per-capability tests,
performance evidence, and rejection of any capability whose correctness cannot
be demonstrated.

## Concrete code targets

- Select candidates only from the catalog: Accounts profile reads, Notifications historical inbox reads, and explicitly approved Expense Core historical/search reads.
- Modify each owning query port/store, repository projection, service `application.yml`, and focused tests; leave credentials, balances, membership authorization, sync, idempotency, claims, and delivery decisions on the writer.
- Update REST/OpenAPI/GraphQL freshness documentation only when externally observable behavior changes.
