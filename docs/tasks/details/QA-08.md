# QA-08 — Production and WebSocket protocol validation follow-up

## Objective

Close the evidence gaps intentionally left outside local QA-07 execution:
production-scale capacity, failover/restore, security scanning, deployment
rollback, WebSocket malformed-frame and duplicate-operation semantics,
sustained backpressure, replay-after-reconnect, and application-level timeout
and retry policy.

## Dependencies

- QA-07
- OPS-20

## Acceptance criteria

1. A production-like execution environment and test data policy are approved.
2. Capacity, failover, restore, security-scan, and rollback evidence is
   captured with explicit thresholds and artifacts.
3. WebSocket malformed-frame, duplicate-operation, backpressure,
   replay-after-reconnect, timeout, and retry semantics are defined by contract
   or recorded as accepted implementation limitations.
4. Results and residual risks are linked from the quality matrix without
   relabeling local Docker evidence as production evidence.

## Status

In progress. The production validation framework has been established in
`docs/quality/production-validation.md`:
1. **Target Environment & Test-Data Policy**: Approved multi-replica topology baseline (3–12 replicas per service, 1 primary + synchronous standby PostgreSQL, 3-node RabbitMQ quorum cluster, multi-replica OIDC IdP) and strict test data policy (zero production PII, ISO 4217 minor-unit deterministic financial fixtures, and zero-sum balancing).
2. **WebSocket & GraphQL Real-Time Protocol Specification**: Contracts and handling semantics defined for malformed frames (RFC 6455 closure codes 1007/1002), malformed GraphQL payloads (operation-scoped error envelopes), duplicate subscription IDs (stream cancellation/replacement), sustained backpressure (bounded 64-item buffers with best-effort dropping without financial corruption), reconnect replay (stateless socket model requiring explicit REST cursor snapshot recovery), and heartbeat keepalive (30s ping/pong with 60s idle disconnect).
3. **Operational Release Gates & Procedures**: Rehearsal procedures documented for capacity soak/burst (`make load-k6`), database failover and point-in-time restore, container security scanning, and additive backward-compatible deployment rollback.
4. **Evidence Integrity**: All local Docker results remain cleanly segregated from target-environment production guarantees, adhering to Evidence Classification Level 4/5 standards.
