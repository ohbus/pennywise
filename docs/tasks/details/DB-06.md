# DB-06 — Split Expense Core command and query ports

Separate application command/query ports and handlers for groups, membership,
expenses, settlements, search, recurring work, synchronization, audit, and
outbox. Preserve aggregate transaction boundaries and writer-only financial,
authorization, lock, claim, idempotency, and revision operations.

Acceptance proves no controller/service selects a datasource, commands cannot
use readers, DTOs replace entity leakage, all result sets are bounded, and
existing Expense Core tests plus PostgreSQL concurrency tests pass.

## Concrete code targets

- Split `expenses/ExpenseStore.kt` into command/query-facing ports while preserving compatibility adapters during migration.
- Refactor `JpaExpenseStore.kt` methods into command handling versus read projection methods; inspect its create/update/delete/materialization methods and read methods near the existing read-only transactions.
- Refactor `groups/GroupStore.kt`/`JpaGroupStore.kt`, `settlements/SettlementStore.kt`/`JpaSettlementStore.kt`, `sync/JpaSynchronizationStore.kt`, `search/SearchStore.kt`/`JpaSearchStore.kt`, and recurring service/repositories.
- Mark `GroupRepository.findLockedByGroupId`, `OutboxRepository` locks, `RecurringExpenseScheduleRepository` due claims, idempotency lookup/claim, and settlement recording as writer-only operation metadata.
- Update `ExpenseController`, `GroupController`, `SearchController`, `SettlementController`, `SyncController`, and recurring controllers only to call handlers, never route databases.
- Extend `JpaExpenseStoreTest`, `JpaGroupStoreTest`, `JpaSettlementStoreTest`, `JpaSearchStoreTest`, and the existing PostgreSQL concurrency tests with route assertions.
