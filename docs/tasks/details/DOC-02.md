# DOC-02: Specify product and service ownership

- Phase: documentation
- Owner role: architecture
- Dependencies: DOC-01
- Owned paths: `docs/product/`, `docs/architecture/`

## Outcome

Document the accepted MVP, future UX journeys, and service/data ownership.

## Implementation requirements

Include households/couples/trips, free forever, placeholders, online all-member edits, immediate repayments, offline read/create, recurrence and per-currency balances.

## Acceptance criteria

Each capability has an owner; future features are explicit; no UI implementation is implied.

## Verification and handoff

Record exact commands, exit status, artifact paths, findings and unresolved blockers
in the task registry. No task is done until its deliverable is reviewed. Use the
approved contracts as the behavioral authority; update the specification and
register child tasks before expanding scope. Future implementation tasks are not
authorized to bypass the documentation gate or the current scaffold milestone.
